# Индексация на эмбеддингах Ollama

## Требование

Индексация должна считать векторы моделью из Ollama. Причина: модель весит
гигабайты, а контейнер `rag` тащил `torch` и `sentence-transformers` только
ради эмбеддингов — на CPU это ещё и десятки секунд на загрузку. Ollama в этом
контуре уже поднята и управляет моделями сама (`ollama pull`).

Решения по конфигурации (подтверждены владельцем):

- модель — `qwen3-embedding:0.6b` (1024 координаты, 639 МБ);
- `sentence-transformers` и `torch` убираются из образа `rag`, эмбеддинги
  идут только через Ollama (бэкенды `tfidf`, `openai`, `sentence-transformers`
  остаются в коде, но не в образе);
- генерация остаётся на OpenAI-совместимом HTTP (`RAGKB_LLM_URL`);
- Ollama живёт на хост-машине, сервиса в Compose нет.

## Поведение

- Значения по умолчанию: `embedding.backend: ollama`,
  `embedding.model: qwen3-embedding:0.6b`,
  `embedding.base_url: http://127.0.0.1:11434`. В контейнере адрес
  перекрывается на `http://host.docker.internal:11434`
  (в `rag` уже есть `extra_hosts: host.docker.internal:host-gateway`).
- Новые параметры: `embedding.timeout` (300 с — первый запрос поднимает
  модель в память), `embedding.keep_alive` (`30m`, чтобы следующий вопрос не
  ждал повторной загрузки), `embedding.retries` (3 — повторы на сетевых сбоях,
  5xx и 429; 4xx не повторяются). Размер пакета остаётся `embedding.batch_size`.
  Все перекрываются `RAGKB_EMBEDDING_*`.
- `Embedder.check()` — предпроверка готовности бэкенда. В `build_index`
  она вызывается **до** разбора документов: полная переиндексация читает и
  чанкует весь корпус, и отказ модели выяснился бы только на первом батче.
  Для Ollama проверка — один `POST /api/show`: он подтверждает, что модель
  установлена, умеет `embedding` (чат-модель в конфиге — частая ошибка) и
  сообщает длину вектора (`<архитектура>.embedding_length`, у
  `qwen3-embedding:0.6b` — `qwen3.embedding_length: 1024`).
- Отказы переводит в `EngineUnavailable` (HTTP 503) с текстом, по которому
  можно действовать: `Ollama недоступна по адресу … (ConnectError). Запустите
  ollama serve или укажите её адрес в RAGKB_EMBEDDING_URL`;
  `Модель «…» не установлена — выполните: ollama pull … Установлены: …`;
  `Модель «…» в Ollama не считает эмбеддинги (умеет: completion, tools)`.
  Фронтенд показывает это как «База знаний недоступна: …» — раньше на таком
  сбое был безымянный 500.
- Ответ `/api/embed` сверяется с запросом: если векторов пришло меньше, чем
  текстов, сборка останавливается, а не пишет в индекс сдвинутые чанки.
  Длина вектора после успешного запроса запоминается и больше не пробуется.
- Смена модели эмбеддингов остаётся запретом на поиск по старому индексу
  (`embedder.name` в манифесте), и к нему добавлена проверка **длины вектора**
  (`manifest["dim"]`): раньше `tfidf_dim`, изменённый без переиндексации,
  давал индекс на 4096 координат с запросами на 2048 — падение на арифметике
  вместо объяснения.
- Тесты не зависят от Ollama: autouse-фикстура `isolated_environment` ставит
  `RAGKB_EMBEDDING_BACKEND=tfidf` (её получают и `Settings()`, собранные
  тестами вручную), а тесты `OllamaEmbedder` подменяют транспорт
  `httpx.MockTransport` — проверяются пакеты, порядок, префиксы,
  размерность из `/api/show`, повторы и тексты отказов.

## Проверка результата

Выполнено на живом Ollama 0.32.14 (`qwen3-embedding:0.6b`, локально):

- `pytest` — 172 теста; `ruff` и `mypy` не добавили новых замечаний
  (13 и 2 находки — прежние, в файлах вне этой правки).
- `POST /api/v1/index/rebuild` на реальном документе (FAQ, 144 чанка):
  11.1 с на холодную (с загрузкой модели), 8.7 с на второй прогон; манифест —
  `backend: chroma`, `embedder: ollama:qwen3-embedding:0.6b`, `dim: 1024`.
- `POST /api/v1/ask` через BFF: ответ потоком NDJSON за 10.1 с, 4 источника
  со ссылками `[N]`, `warnings: []`, `truncated: false`.
- Отказные сценарии: отсутствующая модель — 503 с `ollama pull` и списком
  установленных моделей; недоступная Ollama — 503
  `Ollama недоступна по адресу http://127.0.0.1:9 (ConnectError)`.

## Ограничения и что осталось за рамками

- Модель эмбеддингов видна в выпадающем списке моделей чата: каталог читает
  `GET /v1/models` у OpenAI-совместимого сервера, а он отдаёт всё, что есть в
  Ollama, включая `qwen3-embedding:0.6b`. Ограничить список можно только
  через `llm.available`, у которого нет перекрытия окружением.
- Реранкер `sentence-transformers` в образе не работает: extra `local-models`
  больше не ставится. Это осознанный выбор — включать его нужно в своём
  окружении (`pip install 'ragkb[local-models]'`).
- Бэкенды `tfidf` (тесты, работа без сети) и `openai` (внешний HTTP)
  сохранены; `sentence-transformers` оставлен для локальных запусков.

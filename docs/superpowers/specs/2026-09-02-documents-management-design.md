## Зачем

Сегодня документы корпуса кладут в `data/docs/` файлами и перестраивают
индекс одной кнопкой «Перестроить индекс» в шапке. Владелец базы не видит
состояния корпуса: какие файлы проиндексированы, какие новые, какие
пропущены и почему. Фича даёт страницу админа «Документы»: список файлов
со статусом, загрузку нового документа и удаление — база становится
самообслуживаемой, как Knowledge-раздел в крупных системах, но в архитектуре
ragkb и без их кода.

## Границы

**В работе:** страница `/admin/documents` (роль `admin`); список файлов
каталога корпуса со статусом индексации (в индексе / новый / новее
индекса / пропущен при сборке); загрузка файла (multipart) с авто-
переиндексацией; удаление документа (файл + запись в индексе); правка
compose (`data/docs` становится доступным на запись); тесты бэкенда.

**Вне работы:** загрузка **каталогом**/архивом; фоновая очередь переиндексации
(пересборка синхронная, кнопка блокируется на время); per-document текст в
UI (есть модалка источников); версии документов; редактирование текста файла
в браузере; права «user загружает документы» (корпус общий, управляет админ);
веб-скрапинг; OCR-пайплайн (нечитаемые файлы показываются как «пропущен»).

## Ключевые решения

1. **Два состояния одного документа**: файл в каталоге `docs_dir` и запись в
   индексе (манифест). UI показывает оба и их расхождение:
   - файл есть, в манифесте нет → **«новый, не проиндексирован»**;
   - файл есть, в манифесте есть → «в индексе» + число чанков; если mtime
     файла новее `built_at` индекса → **«изменён, нужна переиндексация»**;
   - файла нет, в манифесте есть → «удалён из каталога, висит в индексе»
     (источники у таких ответов и так помечаются «документа больше нет в базе»).
2. **Загрузка и удаление сразу приводят индекс в порядок**:
   - `POST` документа → сохранить файл в `docs_dir` → полная переиндексация
     (`build_index`), вернуть отчёт; это одна синхронная операция, как
     существующая кнопка «Перестроить индекс».
   - `DELETE` документа → удалить файл из `docs_dir` **и** убрать документ из
     индекса: `core/pipeline.remove_document` (Chroma, точечно) либо полная
     пересборка, если `store.backend` не chroma.
3. **Манифест получает время сборки.** В `extra` при `build_index`/обновлении
   пишем `built_at` (ISO) — по нему UI судит, новее ли файл индекса. Для
   старых манифестов без `built_at` считаем «дата неизвестна» и показываем
   статус только «в индексе/нет».
4. **Compose: каталог корпуса становится записываемым.** Сейчас
   `./data/docs:/app/data/docs:ro` — для загрузки меняем на `:rw` (без `ro`).
   Локальный `make backend` уже пишет в свой каталог.

## Контракт

Все ручки под `require_admin` (как `/admin/users`). Корпус один на
организацию — сегмент организации в пути не нужен.

### Список документов

`GET /admin/documents`

```json
{
  "docs_dir": "data/docs",
  "index": "ok",
  "built_at": "2026-09-02T10:00:00+00:00",
  "corpus": [
    { "name": "reglament_otpuska.md", "size": 8123, "mtime": "2026-08-01T09:00:00+00:00",
      "indexed": true, "chunks": 14, "state": "indexed" }
  ],
  "orphans": [
    { "title": "старый.md", "source": "data/docs/старый.md", "chunks": 3 }
  ],
  "skipped": [["data/docs/scan.pdf", "не удалось извлечь текст (возможно, скан без OCR)"]],
  "summary": { "corpus_files": 15, "indexed_docs": 15, "chunks": 213 }
}
```

- `state`: `indexed` | `new` | `stale` (mtime новее `built_at`) | `unknown` —
  вычисляет сервис; `indexed`/`new`/`stale` только когда индекс собран.
- `orphans` — записи манифеста без файла в каталоге.
- `index: "no_index"` — индекс не построен: `corpus` без статусов,
  `orphans`/`skipped` пустые, `built_at: null`.
- `skipped` — из манифеста (`manifest["skipped"]`, пути, упавшие на прошлой
  сборке; `build_index` кладёт `extra` на верхний уровень манифеста).

### Загрузка документа

`POST /admin/documents` — multipart, поле `file`.

- Расширение должно быть в поддерживаемых (`SUPPORTED_EXTENSIONS` в
  `core/loaders.py`: pdf, docx, md, txt, html…). Иначе 400.
- Имя: `Path(file.filename).name` (без путей); при совпадении с существующим —
  перезапись (UI предупреждает). Размер: разумный лимит (например 20 МБ) — 413.
- Успех: 200 с отчётом переиндексации
  `{ "files", "chunks", "skipped", "elapsed_sec" }` (как у `/index/rebuild`).
- Ошибка сборки без единого документа (пустой корпус после загрузки) — 400 с
  текстом; файл при этом сохранён (или откат — решает реализация, описать).

### Удаление документа

`DELETE /admin/documents/{name}` (`name` — URL-encoded имя файла)

- Удаляет файл из `docs_dir` (нет файла → 404) и убирает документ из индекса.
- Для `store.backend: chroma` — точечно через `remove_document` (без полной
  пересборки); иначе — полная переиндексация.
- Успех: 204. Ошибка только файла/индекса — 500 с detail.

## Хранение/слои

- `core/pipeline.py::build_index` — в `extra` для манифеста добавить
  `built_at` (ISO UTC); он, как и `skipped`, попадёт на верхний уровень
  манифеста. `core/store.py` — без изменений (манифест уже пишет `documents`).
- `core/loaders.py::discover`/`SUPPORTED_EXTENSIONS` — общие для загрузки.
- `services/documents.py` — новый `DocumentsService`:
  - `list_documents()`: читает каталог (`cfg.docs_dir`), открывает манифест
    через движок (`get_engine().store.manifest`), считает `state`,
    `orphans`, `summary`; `EngineUnavailable` → `index: no_index`.
  - `upload(file) -> report`: сохранить файл (безопасное имя) → `build_index`
    → `invalidate`.
  - `delete(name) -> None`: удалить файл; `remove_document` для chroma, иначе
    `build_index`; `invalidate`.
- `api/routes/admin.py` (или новый `api/routes/documents.py`, включить в
  `api/router.py` под `require_admin`): три ручки контракта.
- Фабрика `api/deps/services.py`: `documents_service` из `Container`
  (`cfg`, `engine`, `invalidate` — как у `index_service`).
- `frontend/src/routes/admin/documents/+page.svelte`: таблица-список, кнопки
  «Загрузить» (input file), «Удалить» (с confirm), состояние «переиндексация…»
  на время сборки; ссылка в админ-хабе.

## Compose

- `docker-compose.yml`: `./data/docs:/app/data/docs:ro` → без `:ro`
  (запись для загрузки). Остальные тома не трогаем.

## Тесты

- `backend/tests/test_documents.py` (sqlite/локальный каталог, как
  test_pipeline с numpy; для chroma-ветки — тест только когда chroma доступен):
  - `list_documents`: после `build_index` файлы `state: indexed` с числом
    чанков; новый файл в каталоге → `state: new`; изменённый файл (mtime
    новее built_at) → `state: stale`; удалённый из каталога → в `orphans`;
    `skipped` переносится из манифеста; без индекса → `index: no_index`.
  - `upload`: загрузка `.md` сохраняет файл и возвращает отчёт;
    недопустимое расширение → 400; пустой/нечитаемый файл → 400 с текстом.
  - `delete`: файл исчезает из каталога и из манифеста; повторный delete →
    404; не-админ на ручках → 403.
  - архитектура: `services/documents.py` не тянет HTTP/ORM.
- Фронт: ручной проход (страница, статусы, загрузка, удаление, confirm);
  `bun run check` без новых ошибок.

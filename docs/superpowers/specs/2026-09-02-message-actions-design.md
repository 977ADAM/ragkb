## Зачем

У ответа уже есть оценка (👍/👎). Два следующих действия, которых ждут от
диалога: скопировать текст ответа и перегенерировать его — переспросить ту же
модель тем же вопросом и заменить неудачный ответ новым.

## Границы

**В работе:** кнопка «копировать» у сообщений (вопрос и ответ); перегенерация
**последнего** ответа диалога: сервер удаляет старый ответ, стримит новый на
тот же вопрос и сохраняет его; BFF-роуты; тесты бэкенда на удаление и на
новую ручку; правки спеки/README при необходимости.

**Вне работы:** перегенерация не-последнего ответа (линейная история, хвост
обрубать не умеем); ветвление диалогов; «ответить заново с изменённым
вопросом» (это обычный новый вопрос); отмена потока; повторное использование
последнего вопроса при пустом диалоге.

## Ключевые решения

1. **Перегенерировать можно только последний ответ.** История линейная —
   сообщения идут парами «вопрос → ответ». Если разрешить перегенерацию
   середины, пришлось бы решать судьбу хвоста диалога. UI показывает кнопку
   «перегенерировать» только у последнего ответа; сервер это же проверяет.
2. **Сервер сам удаляет старый ответ.** Фронт не трогает историю: `POST`
   перегенерации удаляет последний assistant-ответ на сервере, затем стримит
   новый через обычный механизм и сохраняет его. Иначе в истории остались бы
   «призрачные» пары вопросов.
3. **Копирование — только фронт.** Текст уже на клиенте; `navigator.clipboard`
   с фолбэком на `document.execCommand('copy')` для небезопасного контекста.

## Контракт

### Перегенерация последнего ответа

`POST /organization/{org}/chat_conversations/{cid}/messages/{message_id}/regenerate`

Тело (необязательное, как у обычного вопроса):

```json
{ "top_k": null, "expand": false, "model": null }
```

Поведение сервера:

1. Проверяет владение диалогом (404, если диалог не принадлежит пользователю
   или сообщение не в этом диалоге).
2. Проверяет, что `message_id` — **последний** assistant-ответ (иначе 400:
   «перегенерировать можно только последний ответ»).
3. Удаляет этот ответ из истории.
4. Берёт текст **предшествующего** вопроса (последнее user-сообщение перед
   ответом) и стримит новый ответ на него (тот же NDJSON, что и обычный
   вопрос: `token`…`done`), сохраняя новый assistant-ответ.
5. `done` несёт новый `message_id`.

Ошибки: 401 без сессии; 404 — диалог/сообщение не найдены или ответ не
последний (для не-последнего всё же 400); 400 — некорректные параметры.

## Хранение/сервис

- `domain/ports.py`: в `ConversationRepository` — метод
  `remove_message(message_id, user) -> bool` (удаляет одно сообщение, если
  диалог принадлежит пользователю).
- `db/repos/postgres_history.py`: реализация `remove_message` (join
  `messages.id == conversation.owner == user`).
- `db/repos/ephemeral_history.py`: `remove_message` → `False` (истории нет).
- `services/chat_conversations.py`:
  - выделить общий ход генерации ответа (resolve model → recent_turns →
    `engine.stream_answer` → `_generate`), чтобы и `stream_message`, и
    `regenerate_message` пользовались одним кодом;
  - `regenerate_message(user, org, cid, message_id, *, top_k, expand, model)`:
    проверки из контракта, удаление, повторная генерация без добавления
    нового вопроса.
- `api/routes/chat_conversations.py`: `POST .../regenerate` (StreamingResponse
  NDJSON, как `messages`).

## Frontend

- `Message.svelte`: строка действий над сообщением:
  - у **вопроса** — только «копировать»;
  - у **ответа** — «копировать», «перегенерировать» (только если это
    последнее сообщение и не идёт поток) и существующие 👍/👎.
- `SourcesModal` не меняется; разметка `[N]` — тоже.
- `chat.svelte.js`:
  - `copyMessage(index)` — clipboard;
  - `regenerateMessage(index)` — только для последнего ответа: `busy=true`,
    очистить текст последнего ответа, `POST` в BFF-роут, вычитать поток через
    существующий `consume`, по `done` обновить `message_id`, обновить список
    диалогов.
- BFF: `frontend/src/routes/api/conversations/[id]/messages/[mid]/regenerate/+server.js`
  (POST NDJSON-прокси с телом из фронта).

## Тесты

- `backend/tests/test_message_actions.py` (на sqlite, как test_feedback):
  - перегенерация последнего ответа меняет текст и `message_id` в `done`,
    старый ответ в истории отсутствует;
  - перегенерация не-последнего ответа → 400;
  - чужой диалог/чужое сообщение → 404;
  - `remove_message` удаляет только сообщение владельца;
  - обычный вопрос после перегенерации продолжает работать.
- Фронт: ручная проверка копирования (clipboard) и перегенерации в живой
  сессии; `bun run check` не добавляет новых ошибок (4 известные остаются).

## Зачем

У локального аккаунта есть имя, роль и дата регистрации, но пользователь не
видит их и не может сменить пароль — это умеет только админ через
`/admin/users` (и то только роль). Профиль закрывает оба пробела: страница
с собственными сведениями и смена пароля самим пользователем.

## Границы

**В работе:** страница `/profile` (имя, роль, дата регистрации); смена пароля
(текущий → новый, с инвалидацией **остальных** сессий — текущая остаётся
работать); ручки `GET /auth/profile` и `POST /auth/password`; BFF; ссылка из
шапки по имени пользователя; тесты.

**Вне работы:** смена имени/логина; email и прочие поля (их нет в схеме);
профиль в режиме `proxy` (личность из заголовков, локального аккаунта может
не быть — смена пароля недоступна, 400); «выйти из всех» отдельной кнопкой
(это побочный эффект смены пароля); двухфакторка; аватар.

## Ключевые решения

1. **Смена пароля = «текущий → новый» + инвалидация чужих сессий.**
   Проверяем текущий пароль (иначе 400 «неверный текущий пароль»), меняем хеш
   (Argon2, как при регистрации), удаляем все сессии пользователя **кроме
   текущей** и выдаём свежую куку в ответе — пользователь остаётся в системе,
   а «чужие» вкладки/устройства разлогиниваются.
2. **Профиль — только локальные аккаунты.** В режиме `session` читаем дату
   регистрации из БД. В `proxy` сведения есть из заголовков, но смена пароля
   невозможна (аккаунта в БД нет) → `400`.
3. **Никакой новой миграции**: поля уже есть (`users.created_at`, `role`).

## Контракт

### Сведения о себе

`GET /auth/profile` (сессия или proxy)

```json
{ "username": "ada", "role": "user", "created_at": "2026-09-01T12:00:00+00:00" }
```

- `created_at` — дата регистрации локального аккаунта; в `proxy` без
  локального аккаунта — `null`.
- 401 без сессии.

### Смена пароля

`POST /auth/password`

```json
{ "current_password": "old-pass1", "new_password": "new-pass1" }
```

- Валидация нового пароля как при регистрации: 8–128 символов.
- Ошибки: 401 без сессии; 400 — неверный текущий пароль и попытка смены
  в `proxy`-режиме; 422 — слишком короткий/длинный новый пароль (валидация
  поля, как при регистрации).
- Успех: `204`, в ответе свежая кука сессии (текущая сессия перевыпущена,
  остальные удалены).

## Хранение/сервис

- `domain/ports.py` (`AccountStore`): `get_profile(username) ->
  tuple[str, str, datetime] | None` (role, created_at);
  `delete_other_sessions(username, keep_token_hash) -> None`.
- `db/repos/auth.py` (`PostgresAccounts`): реализации (запрос по `username`,
  удаление сессий `WHERE user_id = … AND token_hash != keep`).
- `services/auth.py` (`AuthService`): `profile(username)` и
  `change_password(username, current, new) -> token` (новый raw-токен после
  инвалидации чужих сессий).
- `api/routes/auth.py`: `GET /profile`, `POST /password` (кука через
  существующие `set_session_cookie`).
- `api/schemas/auth.py`: `ChangePassword` (current/new + валидатор длины).

## Frontend

- BFF: `GET /api/auth/profile`, `POST /api/auth/password` — прокси, как
  `/api/auth/me` и signin.
- Новая страница `frontend/src/routes/profile/+page.svelte`:
  - сведения (имя, роль, дата регистрации);
  - форма смены пароля (текущий, новый, повтор нового);
  - после успеха — подтверждение; ошибки сервера показываются.
- Шапка (`+layout.svelte`): имя пользователя становится ссылкой на `/profile`
  (рядом остаётся «Выйти»).
- hooks.server.js не меняется: `/profile` требует сессию автоматически
  (не входит в `PUBLIC`).

## Тесты

- `backend/tests/test_profile.py` (sqlite, как test_feedback):
  - `GET /auth/profile` возвращает имя, роль и дату регистрации;
  - смена пароля с верным текущим → 204, старый пароль больше не подходит,
    новый подходит;
  - неверный текущий пароль → 400;
  - короткий новый пароль → 422 (как у signup);
  - после смены пароля старая сессия на другом токене не работает,
    текущая — работает;
  - `proxy`-режим: профиль отдаёт `created_at: null`, смена пароля → 400;
  - архитектура: новые методы порта не тянут HTTP/ORM.
- Фронт: ручной проход (открыть профиль из шапки, сменить пароль, выйти и
  войти новым); `bun run check` без новых ошибок (4 известные остаются).

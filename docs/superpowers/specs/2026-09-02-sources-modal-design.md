# Модалка источников: клик по [N] → фрагмент текста

| | |
|---|---|
| Дата | 2026-09-02 |
| Версия | 1 |
| Статус | готово |

## Зачем

Ответ обязан быть проверяемым: маркер `[N]` в тексте и список источников под
ответом говорят, откуда взят ответ, но не показывают сам фрагмент. Пользователь
должен кликнуть по `[N]` (или по пункту списка) и увидеть кусок документа, на
который опиралась модель, — включая страницу и заголовок раздела. Это усиливает
ключевое свойство ragkb «обязательные ссылки» и закрывает разрыв с тем, как
устроены citation-модалки в больших системах, но остаётся своей реализацией.

## Границы

**В работе:** текст фрагмента в источнике (`text`); кликабельные `[N]` в тексте
ответа; кликабельные пункты списка источников; модалка с деталями источника
(номер, цитата-заголовок, файл, страница, фрагмент, пометка «документа больше
нет в базе»); закрытие по Esc/клику мимо; тесты бэкенда на новое поле.

**Вне работы:** открытие файла/просмотр документа целиком; подсветка точного
предложения в фрагменте; предпросмотр PDF; «перейти к источнику в списке» из
текста; изменение формата хранения старых сообщений (у них `text` нет —
модалка покажет то, что есть); аналитика кликов; экспорт.

## Данные источника

Сегодня источник (в событии `done` и в сохранённом сообщении):

```json
{ "n": 1, "citation": "Регламент отпусков > Ежегодный / с. 3",
  "source": "data/docs/reglament_otpuska.md", "page": 3, "score": 0.9123 }
```

`citation()` уже собирает «Документ > Раздел / с. N» и не дублирует заголовок.
`title` во фронте не приходит — список под ответом показывает путь файла.

Решение: **источник получает поле `text`** — текст чанка, который видел LLM
(`chunk.text`, тот же, что уходит в промпт). Это снапшот на момент ответа:
если документ потом удалили (`available: false`), фрагмент всё равно виден —
проверяемость сохраняется. Размер: чанк ограничен конфигом `chunking.size`
(900 символов), цитируется обычно 1–5 источников — для JSON сообщения это
приемлемо.

Контракт источника после изменения:

```json
{ "n": 1, "citation": "…", "source": "…", "page": 3, "score": 0.9123,
  "text": "Ежегодный оплачиваемый отпуск предоставляется…" }
```

Поле добавляется **только вновь генерируемым** ответам. Старые сообщения не
переписываются: модалка для них покажет `citation`/`source`/`page`/`available`
без фрагмента и подпись «фрагмент не сохранён».

## Backend

- `core/pipeline.py::_cited_sources` — добавить в словарь источника
  `"text": hit.chunk.text`.
- Ничего больше не менять: `done` собирает `used_sources` из этого же места,
  сообщение сохраняет `sources` как есть, `GET …/chat_conversations/{cid}`
  возвращает их (с уже добавленным `available`).

## Frontend

### Кликабельные [N]

Текст ответа рендерится сейчас как простой текст (`<p class="text">` с
`pre-wrap`). Добавить разметку: разбить `message.text` по маркерам
`[N]` (регэксп `\[(\d+)\]`), где `N` есть в `message.sources` — рисовать
кнопку/ссылку `[N]`, открывающую модалку источника; маркер без источника
остаётся текстом. Стриминг: разметку применять к готовому тексту, не к
недописанному (при `streaming` рендерить как сейчас).

Реализация без HTML-инъекции: собрать массив сегментов `{text | cite}` и
отрисовать через `{#each}`; фрагменты текста вставлять как текст (не `{@html}`).

### Модалка

Один экземпляр на сообщение (состояние в `Message.svelte`):
`openSource: Source | null`. Открывается:
- кликом по `[N]` в тексте ответа;
- кликом по пункту списка источников под ответом.

Содержимое:
- заголовок: `[N]` + `citation`;
- путь файла `source`, страница `page` (если есть);
- фрагмент `text` (если есть), иначе «фрагмент не сохранён»;
- если `available === false` — пометка «документа больше нет в базе»
  (фрагмент, если сохранён, показываем всё равно);
- кнопка закрытия; закрытие по `Escape` и клику по фону.

Модалка — лёгкий оверлей (без сторонних библиотек), стили в духе текущего UI.
